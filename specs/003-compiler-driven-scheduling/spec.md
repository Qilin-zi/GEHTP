# Feature Specification: Compiler-Driven Scheduling

**Feature Branch**: `003-compiler-driven-scheduling`

**Created**: 2026-09-28

**Status**: Draft

**Input**: "spec 三件套规划：① op 级 engine 赋值（IR/blob 里的字段，成本模型按形状+VTCM 预算+单元争用定）；② 静态 VTCM carve 时间表 + 显式 DDR↔VTCM move op；③ 显式 fallback"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 编译器决定每个算子用哪个计算单元 (Priority: P1)

模型部署工程师今天遇到的问题是：一个模型在目标 DSP 上跑的时候，每个算子（矩阵乘、卷积、逐元素等）到底用标量、向量、还是矩阵加速单元，是**运行期临时决定**的；运行期决定不了时就**悄悄退回最慢的标量路径**，编译的人对此完全不可见。结果是"模型能跑，但不知道哪些算子没加速、为什么没加速、整体能有多快"。

这个 story 让编译器在编译时就把每个算子的计算单元定下来、写进编译产物；设备端执行时照着编译器的决定走，不再自己做主。

**Why this priority**: 它直接消除"静默回落"这个最痛的不可见问题，是后面两件（内存规划、显式回落）的前提——没有编译期的单元决定，就谈不上为它规划内存，也谈不上"回落"的定义。

**Independent Test**: 编译一个模型，检查编译产物里每个算子都带有计算单元标注；把模型放到目标设备跑一遍，逐算子核对"实际用的单元 == 编译期标注的单元"，100% 一致即通过。

**Acceptance Scenarios**:

1. **Given** 一个编译好的模型，**When** 放到目标设备执行，**Then** 每个算子的实际计算单元与编译期标注一致（逐算子核对，无未计划的替换）。
2. **Given** 一个形状不满足加速单元对齐要求的算子，**When** 编译该模型，**Then** 编译器在编译期把它标注为慢速单元（而非运行期才临时决定），且这一决定在产物里可见。
3. **Given** 两个算子争用同一个计算单元，**When** 编译该模型，**Then** 编译器给出的单元分配是确定的、可复现的，同一份模型两次编译产出一致的分配。

---

### User Story 2 - 编译器规划片上内存并显式搬运数据 (Priority: P2)

今天，DSP 上的片上高速内存是运行期"谁先来谁占全部"：两个算子族想用同一块片上内存时，靠运行期互相让位，编译期完全不规划。结果是不确定的争用、以及可能因此导致的静默性能退化。

这个 story 让编译器在编译时产出一份片上内存使用时间表（哪个算子的数据在哪个时间段驻留在片上内存的哪个区间），并在需要时插入**显式的搬进/搬出步骤**；设备端照着这份表执行，而不是运行期现抢。

**Why this priority**: 它消除片上内存的运行时争用，使数据搬移变得可预测。它依赖 P1 的"编译器已决定每个算子用什么单元"（才知道一个算子到底需不需要片上内存、需要多大）。

**Independent Test**: 编译一个模型，检查产物里含片上内存时间表和显式搬移步骤；放到目标设备跑一遍，核对没有内存区间重叠冲突、搬移按计划发生。

**Acceptance Scenarios**:

1. **Given** 一个编译好的模型，**When** 查看其编译产物，**Then** 每个算子用到的片上内存区间是编译期确定的，且生命周期重叠的算子不占用重叠区间。
2. **Given** 一个需要把数据搬进/搬出片上内存的算子，**When** 在目标设备执行，**Then** 数据搬移按编译期插入的步骤发生（而非运行期临时决定）。
3. **Given** 一个单个算子数据超过片上内存容量的场景，**When** 编译该模型，**Then** 编译器在编译期将其切分，每片按时间表分时使用片上内存。

---

### User Story 3 - 显式回落（绝不静默） (Priority: P3)

今天，运行期做不到编译器计划时（加速单元被占、形状不符、内存不够），会**悄悄退回标量路径**：性能悬崖看不见，数值结果也可能在不知不觉中改变。工程师只能从最终耗时或输出偏差事后反推，定位成本极高。

这个 story 把"回落"变成一个显式契约：编译产物里为每个算子记录"允许回落"或"禁止回落"以及回落到哪里；运行期一旦不能按计划执行，要么按记录的策略回落并**上报偏差**，要么直接**报错**，绝不静默。

**Why this priority**: 它是让 P1 和 P2 真正可靠的纪律保障——有了它，"编译器说了算"才不是一个靠运行期自觉的约定，而是有强制力和可见性。

**Independent Test**: 人为构造一个运行期无法满足计划的场景，核对：被标"允许回落"的算子按记录策略回落且被记录；被标"禁止回落"的算子明确报错而非静默换单元。

**Acceptance Scenarios**:

1. **Given** 一个被标注"允许回落"的算子，其计划单元在运行期不可用，**When** 执行，**Then** 它按记录的策略回落到指定替代单元，且这次偏差被记录（含原因）。
2. **Given** 一个被标注"禁止回落"的算子，其计划单元在运行期不可用，**When** 执行，**Then** 执行失败并明确报错，而非静默换成别的单元。
3. **Given** 一次完整模型执行，**When** 执行结束，**Then** 工程师能拿到一份逐算子报告：每个算子实际用了哪个单元、是否偏离了编译期计划、偏离原因是什么。

---

### Edge Cases

- **对齐不满足**：一个算子的形状不满足加速单元的对齐要求——必须在编译期被分配到慢速单元，而不是运行期才发现并临时回落。
- **单算子超内存**：单个算子的数据超过片上内存容量——必须在编译期切分，而不是运行期失败或静默换路。
- **生命周期重叠**：两个算子生命周期重叠且都要用片上内存——时间表必须保证它们的驻留区间不重叠，否则就是编译期规划错误。
- **计划单元不可用**：运行期加速单元被占或不可用——必须走"允许回落→上报"或"禁止回落→报错"两条路之一，任何情况都不得静默。
- **回落改变数值**：某算子的回落路径用了不同的累加精度，导致数值结果漂移——对被标"禁止回落"的算子这必须视为硬错误；对"允许回落"的算子必须在报告里标注数值敏感。
- **旧模型兼容**：用旧版编译器编译出的模型，放到新运行时上必须仍能原样执行，产物格式向后兼容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 编译器 MUST 在编译时为模型中的每一个计算算子确定其使用的计算单元（"指派单元"）。
- **FR-002**: 编译产物 MUST 逐算子记录该"指派单元"。
- **FR-003**: 设备端执行器 MUST 在指派单元可用时，让每个算子按其记录的指派单元执行。
- **FR-004**: 执行器 MUST NOT 静默替换为别的单元；任何替换 MUST 遵循产物里记录的回落策略。
- **FR-005**: 编译器 MUST 产出一份片上内存使用时间表（哪个算子的数据在哪个时段驻留于片上内存的哪个区间），而非把片上内存分配留给运行期仲裁。
- **FR-006**: 编译器 MUST 为需要进出片上内存的数据显式生成搬移步骤。
- **FR-007**: 执行器 MUST 逐算子报告实际使用的单元，以及相对指派单元的任何偏差及原因。
- **FR-008**: 编译器 MUST 能对算子组标注"禁止回落"，使执行器在无法按计划执行时明确失败，而非替换单元。
- **FR-009**: 旧版编译器产出的模型 MUST 能在新执行器上继续原样执行（产物格式向后兼容）。
- **FR-010**: 无论算子用指派单元还是回落单元执行，数值输出 MUST 等价（不得出现静默的数值漂移）。

### Key Entities

- **算子 (Operator)**: 模型中的一个计算步骤（如矩阵乘、卷积、逐元素运算）。属性：形状、指派计算单元、回落策略（允许/禁止及替代单元）。
- **计算单元 (Compute Unit)**: 平台提供的执行资源之一（标量、向量、矩阵加速）。每个算子指派其一。
- **编译产物 (Compiled Artifact)**: 编译器的输出——算子列表及逐算子单元指派、片上内存时间表、显式数据搬移步骤。
- **片上内存时间表 (On-Chip Memory Schedule)**: 算子/数据随执行时间对片上内存区间的占用映射，保证重叠生命周期不冲突。
- **数据搬移步骤 (Data Movement Step)**: 数据在片外内存与片上内存之间的一次显式转移。
- **执行报告 (Execution Report)**: 逐算子记录实际所用单元及相对计划的任何偏差。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对一个编译好的模型，100% 的算子按编译期指派单元执行（零未计划的替换），由逐算子执行报告验证。
- **SC-002**: 若有任何替换发生，100% 的替换在执行报告中可见并附原因——不存在静默替换。
- **SC-003**: 端到端执行耗时相对改动前基线不退化；此前被静默退回慢速路径的算子类改用加速路径（例如注意力里的矩阵乘从慢速路径转入加速路径，耗时显著下降）。
- **SC-004**: 输出数值质量（相对参考输出的相似度）相对改动前基线不变，无回归。
- **SC-005**: 一份用旧版编译器产出的模型，放到新执行器上运行时，产出与原执行器逐字节一致的输出。

## Assumptions

- 本能力在现有的 0.8B 参数模型上验证，但设计为通用的、模型无关的能力。
- 编译产物格式的向后兼容是硬约束（现有产物重新生成成本高）。
- 三件套分阶段交付：先单元指派，再片上内存规划，再显式回落。
- 计算单元即平台提供的三种（标量、向量、矩阵加速），不假设新增硬件。
- 片上内存是容量已知、总量固定的共享资源，其总容量编译期可知。
