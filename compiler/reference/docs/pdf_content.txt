1 Introduction 
Many software products require safety along with the IVI use cases. Therefore, use the ADAS 
DSP image in all these software products. The dynamic .SOs, which use an unsigned protection 
domain (PD) must perform a cyclic redundancy check (CRC). 
NOTE: CRC addition is required for use cases running in unsigned PD only. Signed PD use cases must 
not add CRC else they fail in signature verification. 
Add CRC inside .so, and check CRC after the .so is loaded into memory for the integrity check to 
ensure that the .so in a file system is correctly loaded into memory. This is required for the NSP 
image safety feature across software products. 
For the safe version of Neural Signal Processor (NSP), there are assumptions of use(s) (AoUs) 
that may change the way the NSP is used as compared to the non-safe implementation. 
鈻?SA8650P, SA8775P: See SA8775P and SA86XXP BSP Software Functional Safety Manual  
(80-PV665-20) for NSP software AoUs. 
See the NSP AoUs related to unsigned PD (AIS60-SWAoU_SI-54); a dynamically loaded user 
module should apply CRC (AIS60-SWAoU_SI-161). 
鈻?SA8255P: See SA8255P.HQX.4.5.6.0 BSP Software Functional Safety Manual (80-PV665-24) for 
NSP software AoUs.  
See the NSP AoUs related to unsigned PD (GID-183537); a dynamically loaded user module 
should apply CRC (GID-196592).

2 Add CRC into the target image 
It is recommended to use the unsigned PD for a safe use case. 
2.1 Add CRC to dynamic libs 
To ensure that the loaded .so on the DSP for unsigned PD is not corrupted, an 
embedded CRC feature for unsigned PD dynamic libs is introduced. 
Use: python swiv_build_utility.py  -i input.so -o out_crc.so 
CRC will be embedded at the end of the elf. 
Assume if you load A.so to DSP, and A.so is dynamically linked with a shared library 
B.so, both A.so and B.so must be CRC-embedded because in the DSP, the CRC 
checks are performed for the main library and on the dependent .so files. 
It is recommended to use the swiv_build_utility.py from the QPM. After adding CRC to the 
dynamic libs, static linking support is discontinued.  
The QXDM鈩?Professional logs show the following error for a module that does not have CRC 
during loading.  
CDSP0: ELF verification section header for CRC segment not found  
CDSP0: CRC validation check failed  
CDSP0: CRC validation has failed for dynamic library libXX.so loading in 
unsigned PD 
An example calculator execution procedure on the FuSa platform is as follows: 
1. Collect the swiv_build_utility.py from QPM, the procedure has been mentioned later in 
this doc. 
2. Open the cmd prompt and generate the new skel.so file using the following command: 
python swiv_build_utility.py  -i input.so -o out_crc.so 
For example:  
python swiv_build_utility.py -i libcalculator_skel.so -o 
libcalculator_skel_new.so 
3. Replace the newly generated skel.so file with the previously pushed file in 
/mnt/etc/images/dsp. 
4. Rename the file with the default skel.so file. 
5. After sync, try the unsigned PD calculator commands, those should work.

3 Installation and usage of SWIV build tool 
3.1 Install SWIV tool 
Regarding the license, the SWIV build utility tool is included in the same product kit with 
Qualcomm漏 Hexagon鈩? If you have access to the Hexagon tool, you can access the SWIV tool 
as well. 
The build tool is published in QPM3, search swiv or asiv in QPM3. The search result lists the 
tool. Install the tool from QPM3. 
 
 
3.2 Use SWIV build tool 
After the installer is run, a Python script is extracted to the target path. The script is compatible 
with Python 2 and Python 3 and no additional library is required. 
At present, all types of images use the default way of adding the CRC as non-loadable. Use 
python swiv_build_utility.py -i {input_img} -o {output_img}.

The SWIV build tool is used to generate the CRC checksum and embed it into the image. The 
checksum is verified by the SWIV runtime library after image loading. 
The following are the basic usage commands: 
python swiv_build_utility.py -i {input_img} -o {output_img} -l -v 
{virtual_addr} -p {physical_addr} 
Add the CRC as loadable. This usage might be needed in a few cases, for example, it is hard for 
the image loader itself to read the ELF file to get the CRC during the verification phase. 
python swiv_build_utility.py -i {input_img} -o {output_img} 
Add the CRC as non-loadable. At present, all types of images use the default way of adding the 
CRC as non-loadable.

4. Clock vote Q&A:
鈻?Which power level need to set ?
鈥?Power level have 7 levels, if you want best performance, choose the maximum 7 (HAP_DCVS_VCORNER_TURBO), otherwise choose 
other levels to save power consumption, depends on your usecase.
鈻?What value should be set for latency value?
鈥?Latency value:  Sleep latency vote in micro-seconds, it鈥檚 time to bring DSP out of sleep mode after it receives an interrupt from CPU.
鈥?Details refer to <hexagon sdk>/doxygen/HAP_power/index.html and <hexagon_sdk>/ 
software/system_performance/system_optimizations.html#dsp-sleep-latency
鈥?Normally we can set value to 10 or 100 both is ok.
鈥?Latency value set to 0 or 65535 will let DSP enter sleep mode immediately, so you can set these values when you want to disable 
CDSP clock
鈻?What鈥檚 difference between DCVS enable or not ?
鈥?DCVS details refer to <hexagon_sdk>/doxygen/HAP_power/index.html
鈥?Disable DCVS will let clock remains constant target_corner value during execution, otherwise DCVS enabled will automatically run 
within range between min_corner and max_corner values to save power consumption.
鈥?When DCVS is HAP_DCVS_V2_POWER_SAVER_MODE and not set latency value to 0 or 65535, DSP will automatically sleep after 
5s when DSP in idle mode.
鈻?Pls remember to call disable DSP clock API when the demo is finish, otherwise there maybe a DSP unsleep issue.
鈻?If run demo and vote DSP with a new handle for each time, pls remember to call HAP_power_destroy in disable DSP clock API, otherwise 
will lead to a clock context leak issue, and after several loops fastrpc will return 0x80000574 error.
