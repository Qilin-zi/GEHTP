§1 调度解决什么问题

一句话：让计算图在片上一小块内存里跑起来

编译器面对的核心问题只有一个：神经网络里成百上千个算子，要在一小块片上高速内存（VTCM）里依次执行。执行顺序决定哪些数据会同时「活着」占用内存；放置方案决定它们能不能都放得下。所以调度的本质，就是找一个执行顺序，让「同时活着的数据」尽量少，峰值内存尽量低。

为什么顺序决定内存

两个大张量如果「生命周期」重叠，就会同时占内存，峰值就高；如果调换执行顺序，让它们一个用完、另一个才开始，它们就能共用同一块内存，峰值就低。编译器不能改图，但能改执行顺序——这正是调度的用武之地。

§2 总流程

走一遍；装不下就重排、再走一遍

整条链只做四件事：分析依赖 → 决定顺序 → 沿顺序放置内存 → 产出执行序列。唯一的分岔在最后一步之前：装不下时，不是立刻报错，而是标记「需要重排」，回到起点换一个顺序再来——因为不同的顺序可能把内存峰值压下去。

最重要的一个判断

决定「要不要再来一轮」的，不是返回值本身，而是内部状态有没有被写成「需要重排」。只有「内存不足 · 可重试」这一类失败会写这个状态，其它失败都不写，所以只走一轮就结束。

§3 排序引擎

怎么算出「这个顺序的内存峰值」

排序引擎的核心直觉一句话：沿着执行顺序一步步走，每步记录「此刻还活着的张量总共多大」，走到最后取最大值——那就是这个顺序的内存峰值。排序的目标，就是让这个最大值尽可能小。

「活着」指的是：已经算出来、并且后面还有算子要用它。一个张量从它被产生算起，直到最后一个用它的算子结束——这段就是它的生命周期。

初始顺序：剥洋葱式拓扑排序

初始顺序用 Kahn 拓扑排序——像剥洋葱一样，每轮剥掉一层「所有前驱都已就绪」的算子：

步骤做什么
1统计每个算子的入度（还有几个前驱没做完）
2入度为 0 的算子进候选队列，按注册顺序排
3弹出队头进入结果顺序，把后继入度减一，减到 0 就入队
4重复直到队空（有环则按注册顺序兜底追加）

两个关键性质：稳定（无依赖的算子保持原始相对顺序）；只保证合法、不优化内存（初始顺序只是「把你给的顺序里能提前的提前」，压峰值交给后面的优化循环）。

§4 优化循环

换新顺序：试一步、量一次、记住最好的

优化循环是「排序」内部的打磨车间。一轮 = 快照 → 提出一个调整 → 验证合法性 → 量峰值 → 更新最优记录 → 回滚 → 决定是否继续。每一次改动都是先快照、试完就回滚，所以无论尝试多乱，原始顺序永远完好。

引擎每轮做什么：七步 + 一个走查例子

「引擎提出一个顺序调整」是整个系统的心脏，也是最容易绕晕的地方。每轮它固定做七件事：先挑「最痛」的一段，再挑最值得挪的那个算子，然后问依赖图一个问题（一个最小割），按答案切割，再修复受影响的内存曲线。

一个例子：一个大张量拖住两个分支

图里有六个算子 a–f，两个「大」张量：a 产出 A（8 grain），被 c 和 d 用；b 产出 B（7 grain），被 e 用；f 汇总 c、d、e 的结果。

初始顺序 a,b,c,d,e,f 的峰值是 16（走到 c 时，A、B、C 同时活着）：

步骤顺序活着的张量总 grain
1aA8
2bA, B15
3cA, B, C16 ← 峰值
4dB, C, D9
5eC, D, E3
6f—0

引擎怎么切（对照七步）：

  1. 挑窗口：痛线是当前峰值的一个比例（此例 5 grain）。A(8)、B(7) 都超线，该窗口计 3×，得分最高。
  2. 挑节点：窗口内挑 b——B 大、权重高，挪它收益最大。
  3. 重分层：清空并重算层级标签，确认 b、e 是下一步的候选。
  4. 问最小割：临时加无限边后，最小割回答「b 和它的消费者 e 必须一起挪，整块可以滑到 d 之后」——B 只有 e 用，挪 b 必须拖 e；A 被 c、d 用，所以 A 不能死在 d 之前。
  5. 切割：切出真子集 {b, e}，从顺序里抽出，注册新组。新顺序 a, c, d, b, e, f。
  6. 修复曲线：只重算受影响段，得到新峰值。
步骤新顺序活着的张量总 grain
1aA8
2cA, C9
3dC, D2
4bB, C, D9
5eC, D, E3
6f—0

发生了什么：a、c、d 连着跑，A 在 d 之后立刻死；b、e 连着跑，B 晚生早死。两个大张量不再同时活着，峰值从 16 降到 9。这就是「重排降峰值」在引擎内部的样子——不是改图，而是把大张量的生命周期错开。

诚实边界

这七步已与真实二进制逐调用交叉核对（反汇编 ↔ 反编译语料），但尚未落到代码：当前引擎仍是占位（第一轮就报「无候选」，循环确定性一轮结束）。一旦这套机制实现，重试才真正有探索空间。

§5 内存分配

有多少内存池、各管什么、内部怎么管

把内存的两重世界分开，问题就清楚了：宿主机内存（编译器自己运行时用的真内存）和DSP 片上内存的「账本」（编译期从不碰真实地址，只规划谁放哪，偏移算好后由后端填真实地址）。账本有三个，加宿主机池共四个池；溢到片外 DDR 的也不是没人管——常量池有近/远之分，溢出的张量有 arena。

池管什么内部怎么管
宿主机记账池 编译器自己的数据结构（账本本身、各种表） 每个池默认 8 MiB、256 字节对齐、向上堆；放不下就开新池；超大请求独占一池
生命周期账本 中间张量在片上内存的偏移 维护「可用区间表」，每个区间记四件事：起点、大小、前任何时死、后任何时生；复用标准是时间完全不重叠；放不下的从高水位线向上堆，只升不降
常驻块池 从头活到尾的常量 / 权重块 按 256 字节单位管区间表：分配取第一个放得下的区间头，释放与左右邻合并；还跟踪「最大连续空闲」当快速闸门
最终放置账本 每个块在片上内存的最终位置 块号先在 minimap 里登记去重；每块 2 KiB 对齐；累计总量守预算

三个账本各管一段，互不重叠

中间张量进生命周期账本（生命周期有起有落，可以错开复用）；常量 / 权重进常驻块池（全程活着，没有复用机会，直接头尾紧挨着打包）；最终放置账本做总校验（把前两个的结果对着预算称重）。「放不下 · 可重试」的判定只来自最后一个账本。

串起来

顺序决定生命周期如何重叠 → 生命周期决定谁复用谁的内存（账本一）→ 复用程度决定总需求 → 总需求过不过预算（账本三）决定要不要重排重试。这条因果链的头是「顺序」，所以重试动作是「重排」，不是「缩小张量」。
